# 猫鼠手环 V1.5 通信协议

所有多字节整数均为**小端序**（NFC APDU 除外，APDU 遵循 ISO 7816 标准）。

## 1. BLE GATT

广播名：`CMB-XXXX`（XXXX 为手环 ID 后两字节）

| 名称 | UUID | 属性 | 说明 |
|---|---|---|---|
| Service | `7a3e0001-5c1d-4b8e-9a2f-6c4d1e0b9a10` | | |
| CMD | `7a3e0002-5c1d-4b8e-9a2f-6c4d1e0b9a10` | Write / WriteNoRsp | 手机 → 手环指令 |
| EVENT | `7a3e0003-5c1d-4b8e-9a2f-6c4d1e0b9a10` | Notify | 手环 → 手机事件 |
| INFO | `7a3e0004-5c1d-4b8e-9a2f-6c4d1e0b9a10` | Read | 手环信息快照 |

### 1.1 角色 Role

| 值 | 角色 | 默认灯效 |
|---|---|---|
| 0 | LOBBY 大厅 | 未连接：白色慢闪；已连接：青色呼吸 |
| 1 | CAT 猫 | 红色旋转 |
| 2 | MOUSE 鼠 | 绿色呼吸 |
| 3 | JAILED 被抓 | 蓝色闪烁 |
| 4 | OUT 出局 / 观战 | 紫色微光，NFC 关闭 |

### 1.2 指令 CMD（手机写入）

格式：`[opcode, 参数...]`

| opcode | 名称 | 参数 | 说明 |
|---|---|---|---|
| 0x01 | SET_ROLE | role u8, team u8 | 切换角色，自动切换灯效 |
| 0x02 | SET_SESSION | session u32 | 场次 ID，写入 NFC 握手，用于防止跨场误读 |
| 0x03 | LED | effect u8, r, g, b, durMs u16 | durMs=0：设为常驻灯效；>0：临时叠加 |
| 0x04 | HAPTIC | pattern u8 | 见 1.4 |
| 0x05 | BUZZER | pattern u8 | 见 1.4 |
| 0x06 | NFC_WINDOW | mode u8, durMs u16 | 0 = 按角色自动，1 = 强制读卡，2 = 强制卡模拟 |
| 0x07 | IMU_THRESHOLD | mg u16 | 碰撞阈值，默认 2000 mg，保存到 NVS |
| 0x08 | IDENTIFY | — | 彩虹灯 + 振动 + 蜂鸣，用来找到自己的手环 |
| 0x09 | BIND_URL_BEGIN | utf8 字节 | 开始写入绑定 URL 前缀（清空旧值） |
| 0x0A | BIND_URL_APPEND | utf8 字节 | 追加（MTU 较小时分包发送） |
| 0x0B | BIND_URL_COMMIT | — | 保存到 NVS 并生效 |
| 0x0C | POWER_OFF | — | 进入深度睡眠，按键唤醒 |
| 0x0D | BRIGHTNESS | max u8 | 灯环最大亮度 0~255，保存到 NVS |
| 0x0E | STANDALONE | on u8 | 断开手机时是否启用本地规则（默认开） |

LED effect：0 OFF，1 SOLID，2 BREATHE，3 BLINK，4 SPIN，5 FLASH，6 RAINBOW

每条指令执行后，手环都会回一个 ACK 事件。

### 1.3 事件 EVENT（手环通知）

格式：`[type, seq, 数据...]`，seq 每条事件自增（0~255 循环），用于去重。

| type | 名称 | 数据 | 说明 |
|---|---|---|---|
| 0x01 | BOOT | fwMajor, fwMinor, role | 连上手机后发送 |
| 0x02 | BUTTON | kind u8 | 1 短按，2 双击，3 长按 |
| 0x03 | IMPACT | peakMg u16 | 检测到碰撞 |
| 0x04 | NFC_PEER | dir u8, peerId[6], role, team, session u32, flags | dir=0：我读到了对方；dir=1：对方读了我 |
| 0x05 | NFC_ITEM | uidLen, uid[7], data[8] | 读到道具卡（NTAG 第 4 页起 8 字节） |
| 0x06 | BATTERY | mV u16, pct u8 | 每 30 秒一次 |
| 0x07 | NFC_BIND_READ | — | 手机通过 NFC 读取了绑定 URL |
| 0x08 | ACK | opcode, result | result：0 成功，1 参数错误，2 未知指令 |
| 0x09 | ROLE_CHANGED | role, team, reason | reason：0 指令，1 本地规则，2 按键调试 |

### 1.4 振动 / 蜂鸣图案

| id | 名称 | 场景 |
|---|---|---|
| 0 | TICK | 轻触确认 |
| 1 | DOUBLE | 按键双击 |
| 2 | CAUGHT | 被抓（长振） |
| 3 | RESCUED | 被救（三连递增） |
| 4 | HEARTBEAT | 猫在附近 |
| 5 | COUNTDOWN | 倒计时滴答 |
| 6 | ITEM | 捡到道具 |
| 7 | ERROR | 失败 / 无效操作 |
| 8 | CATCH_OK | 抓捕成功 |
| 9 | START | 游戏开始 |

### 1.5 广播包厂商数据

`FF FF 'C' 'M' role team battPct sessionLo sessionHi`

手机可以在不连接的情况下扫描附近手环，并获知其角色。用法：“猫在约 10 米内 → 鼠的手环心跳振动”。

## 2. NFC 协议

### 2.1 手环 ↔ 手环（ISO 14443-4 自定义 APDU）

| 步骤 | 方向 | APDU |
|---|---|---|
| 1 | 读卡方 → 被读方 | `00 A4 04 00 07 F0 43 4D 42 41 4E 44 00`（SELECT "CMBAND"） |
| | 被读方 → 读卡方 | `90 00` |
| 2 | 读卡方 → 被读方 | `80 10 00 00 0C [id6 role team session4] 00`（HELLO） |
| | 被读方 → 读卡方 | `[id6 role team session4 flags] 90 00` |

握手后双方都会上报一个 `NFC_PEER` 事件（一个 dir=0，一个 dir=1），服务器可以交叉核对。

### 2.2 手机 ↔ 手环（NFC Forum Type 4 NDEF 卡模拟）

- NDEF AID：`D2 76 00 00 85 01 01`
- CC 文件 `E103`，NDEF 文件 `E104`（只读）
- 内容：URI 记录 `<BIND_URL 前缀><手环 ID 十六进制>`，默认 `https://example.com/b?id=XXXXXXXXXXXX`

### 2.3 道具卡（NTAG213/215）

- 推荐在第 4 页起写入 8 字节：`'C' 'M' 'I' itemType itemId(2) reserved(2)`
- 手环原样上报 UID 和这 8 字节，由服务器决定道具效果（也可以只用 UID 在后台登记）

## 3. 与现有 `new_cat` 小程序 / v2 后端对接

现有微信试点（API 0.6.1，分支 `codex/general-native-map`）已具备完整的房间管理、实时地图、50 米 GPS 校验、5 秒位置新鲜度与动态码抓捕闭环。硬件手环作为**外设交互层**无缝接入，不破坏现有扫码兜底与 230 项回归基线：

### 3.1 对局状态与手环灯效/角色映射

| 现有小程序 / v2 状态 | 下发手环 `SET_ROLE` / 指令 | 手环默认反馈 |
|---|---|---|
| 房间准备（`ready`） | `ROLE_LOBBY` | 未连蓝牙白灯慢闪；已连青灯呼吸 |
| 躲藏阶段（`hiding`，30s） | 保持本局阵营 + `LED` 叠加倒计时 / 提示 | 倒计时滴答振感与蜂鸣 |
| 追逐阶段 · 猫（`cat`） | `ROLE_CAT` | 红灯旋转；碰撞/按键触发 NFC Poll |
| 追逐阶段 · 鼠（`mouse`） | `ROLE_MOUSE` | 绿灯呼吸；碰撞/按键 Listen/Poll 交替 |
| 近距预警（`alert`） | `HAPTIC(PAT_HEARTBEAT)` | 心跳振感（可由服务端预警或近场 BLE 广播触发） |
| 被捕出局（`captured`） | 传统模式 `ROLE_OUT` / 解救模式 `ROLE_JAILED` | 长振报警；解救模式下蓝灯闪烁等待队友碰触解救 |
| 失联暂停（`paused`） | `LED(BLINK, 黄色)` | 暂停警示 |

### 3.2 抓捕与反作弊裁决（复用 `api/v2`）

收到手环 `EVT_NFC_PEER` 时：
1. 校验场次 `session` 一致、角色组合合法（`CAT` 读 `MOUSE` = 抓捕；解救模式下 `MOUSE` 读 `JAILED` = 解救）
2. 小程序复用现有 `POST /api/v2/rooms/:id/capture`（后续可扩展 `proofType: "nfc"` 字段，兼容现有动态码 `/token` 兜底）
3. 服务端继续沿用现有 **50 米 GPS 距离/精度门槛 + 5 秒位置新鲜度** 反作弊校验，并对 3 秒内双端上报去重
4. 裁决通过后，小程序向手环下发 `SET_ROLE`、`HAPTIC`、`LED` 同步状态

断开手机时（`STANDALONE`=1），手环按本地猫抓鼠/解救规则独立运行，方便现场脱离小程序直接测试硬件。
