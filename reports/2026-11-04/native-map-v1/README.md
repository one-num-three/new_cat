# 通用微信实时地图版本 · native-map-v1

## 使用

创建活动 →「使用实时地图」→ 原生微信地图上切换“选择集合点”/“框选范围” → 依次点3–16顶点 →「使用这个范围」→ 创建并邀请。也可在“场地地图”下拉选“通用实时地图”。可点“用我位置”采集真实GCJ-02位置并移动到本人；无需美术地图、校区配准或预制图片。原有三张艺术地图保持可选。

开始游戏后，原生地图显示本人、授权队友、可选共享视野中的猫、猫队周期区域线索、集合点与活动多边形。原生单指移动/双指缩放由微信map组件处理。定位停止、出局、暂停、重连、动态码抓捕、动态目标、结算与新一轮沿用现有权威流程。

## 范围与权限

地图id为native-gcj02-v1，稳定revision同名；API version保持0.6.1，增加capabilities.nativeMapVenues=true。服务端地图目录登记native-only图层。支持GCJ-02有效坐标，不受三张校区图的包围盒限制；通用场地必须提交多边形而不能漏填边界。面积400平方米至4平方公里，3–16顶点，顶点间至少5米、距集合点不超过3公里，边界不交叉，集合点必须在内。实际可通行/水面/道路/禁入区由组织者到场确认。

只有房主可修改范围，进行中不可修改；保存后全员重新准备并清旧位置。越界容差与失联暂停沿用原规则。普通玩家不能改变身份、胜负或通过切图取得敌方位置。通用地图没有图片标定入口；服务端拒绝标定请求。

## 限制与部署

通用地图赛后支持CSV/GeoJSON导出，本版没有预制艺术底图，故不提供艺术轨迹海报；不拿玄武湖图片冒充任意场地。旧地图海报功能保持。原生地图底图覆盖和定位能力受微信平台/设备影响。

完整前端：frontend/MODIFIED_FILE（含全部分包）。工程入口仍D:\cat-mouse-miniprogram。后端启动入口cat-mouse-server/v2/server.js，安装npm ci，配置DATABASE_URL等变量方式沿用仓库README/.env.example；npm --prefix cat-mouse-server test可复跑。前后端须配套更新，旧线上服务器不认识新mapId。本轮只实现、测试、GitHub版本上传，未部署线上服务或上传/发布微信代码。
