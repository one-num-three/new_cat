## 2. 优先结论

1. **P1：准备页标题后方的青色横矩形**是最明显的残差，素材透明擦除区露出了天空色衬底。应修衬底或恢复同源浅纸色裁片，不移动整个标题掩盖问题。

3. **P1：bigfont 三列目标尚未成立。** 正常截图确实三列且文字清楚；读取的 `.fontLarge .previewItem` 明确改为两列，现有正常图不能证明大字体三列可读。
4. **P2：首页提供的截图仍能看见英雄天空横缝。** 父任务已指出首页同源裁片拼接修复已完成；此处记为“待新截图确认”，不以这张快照否定新实现，也不宣称接缝已通过视觉验证。
5. **P2：创建 CTA 仅略晚，不是晚 47 px。** 按内屏相对位置，实际按钮顶部约 727，参考约 721，差约 +6 px；适宜小修，不适宜整页上移几十像素。

### 6.2 bigfont 三列

此轮提供的正常图没有展示 bigfont 状态。当前只读源码明确为：

```css
.fontLarge .previewItem {
  width: calc((100% - var(--vw) * .01538)/2);
  min-height: calc(var(--vh) * .07);
}
.fontLarge .entryTitle { white-space: normal; }
```

因此当前分支大字体会变为**两列**，不能据正常图宣称“大字体三列通过”。

若本轮目标明确保留三列，最小布局方向如下：

1. 恢复 bigfont 卡片宽度的三列公式（正常态已具备）。
2. 只在 `.fontLarge` 把卡片改为竖向：图标在上，标题在下；图标保持原宽高，不放大压缩，箭头绝对定位于右上。
3. 标题保留自然字号与 `white-space:normal`，允许最多自然两行；卡片按文字行数增高。以当前 390 视口估算，三列每卡约 113 px 宽，五字标题在大字号时的自然宽度约 73–84 px，可以在竖向卡片里放下；不需要缩小字形。
4. 正常态继续使用当前横向三列，不改变已经可读的常规布局。页面可纵向滚动，不为强塞一屏压缩字或触控区。
