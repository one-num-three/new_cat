# 02-01 页面高保真复刻：独立视觉审计

审计日期：2026-10-12。审计对象：16 张已选设计稿与上一版 verified 运行截图。**本报告逐张实际读取了 32 张本地 PNG；不是复述上一轮报告。** 仅输出本文与 measurements.json，没有改运行代码、素材、桌面窗口或部署状态。

## 1. 结论与最先应修的缺口

上一版的主要问题是 **素材题材、页面结构和构图比例不一致**，不是“再调一点配色”即可修复。

1. **素材内容错误**：准备、动态码、调试台复用了创建页旗杆场景；参考三页没有旗杆。重连页换成手机重试场景，参考是断链+猫鼠。鼠队追逐页的底部小鼠插画完全缺失。
2. **地图主体失真且偏下**：参考中央集合圆接近圆，上一版是竖椭圆；集合圆心参考约 `(53%W, 44%H)`，实际约 `(52%W, 58%H)`。地图不是只换了一张背景，构图坐标也发生了变化。
3. **结果/异常场景像小贴纸**：躲藏、出局、暂停、重连插画通常只有参考约 65% 的归一化宽度；鼠胜场景应约 64.6%W，实际 43.5%W，并丢掉越出面板上沿的层叠。
4. **取消页布局左右反转**：参考左插画、右标题/胶囊；上一版左标题、右插画。必须单独版式，不应复用胜利页结构。
5. **抽屉高出约 76dp**：参考上沿 41.1%H，实际 32.1%H；缺块标题图标、事件时间戳、首屏退出本局。
6. **字形层级与控件图标退化**：房间码、首页/创建大标题、地图底部主标题偏小；部分名单文字反而偏大。鼠头像被绿色猫头替代，定位针变白点，下拉箭头变字母 v，功能图标被圆点/Unicode 字符替代。

## 2. 对齐与测量规则

- 参考 PNG：1024×1536。统一内屏近似裁切为 `x=156, y=40, w=712, h=1454`；外部背景、硬件黑框、侧键不计。
- 上一版截图：648×1402，对应保存的开发工具布局 390×844dp。直接取完整内屏。
- 表中百分比以两图各自内屏归一化。便于实现的目标盒 `x,y,w,h`（390×844dp）和上一版盒、差值、原图 SHA-256 全部见 `measurements.json`。
- 人工盒是目视估计（约 ±4 原图像素），不是 DOM 精确测量；上一版 DOM 实测同时保存在 JSON 的 `previous_measured_layout_dp`，没有把手测数字冒充精确布局。
- 两图屏幕长宽比约 0.490 与 0.462。**纵向比例用于布局；图片本身只做等比缩放/裁切，禁止把公园或角色非等比拉长。** 多出的屏高由留白/安全区吸收。
- 忽略系统时间、信号状态、刘海和底部系统横条；不忽略 APP 标题、胶囊、色块、插画、图标。数据差异不计视觉扣分，但动态数据仍须保留原生实时渲染。

## 3. 通用部件修正

### 地图与头部（04–07、09–14）

- 参考头部信息板：x≈3.1%W，y≈10.4%H，w≈94%W，h≈8.3%H。上一版位置大致相近，但终局板高度缩成约 7.7%H，需回到同一模板。
- 参考两条分隔线大致在 x=38.5%W、66.0%W；上一版约44.3%W、69.1%W。左阵营列过宽，中列与时钟中心偏移。
- 猫图标要猫头耳朵剪影；鼠追逐/预警/出局要炭灰侧向小鼠头像，鼠胜可用参考圆耳绿色剪影。不能用一枚换色猫头代替所有阵营。
- 参考地图保留天空上沿/远景树梢；上一版大片纯青天空且公园内容整体被放大下移。以桥、亭、集合圆三个地标校准裁切，再放动态标记。
- 集合旗杆：白色细描边 + 白色椭圆地标 + 下方深青“集合点”。取消页是垂下软旗。纯色三角旗不是逐图一致。
- 顶部主时间已接近参考字高，不要全局再把倒计时放大。底部说明、场景标题和详情按钮则需逐页校准。
- 首页/普通房间页左右边距约5.2%W；地图动作按钮约4.5%W。上一版地图按钮3.5%W偏宽。

### 字体、控件、色块

- 保持系统中文文字可选与控件可操作，按照参考的**字形墨迹宽高**调字重/字号/字距，而不是只统一字号。参考标题明显厚重、字面较宽；上一版不少位置是普通粗体。
- 参考按钮有柔和橘色变化和底缘深色3D压边；上一版截图主色块多数接近单色，且橘偏淡/偏棕。参考首页主按钮像素众数 `#E66E3C`，实际 `#E37847`。
- 参考预警底色众数 `#FDECDB`，实际 `#FCF1DF`；参考文字鲜橘，实际偏棕。参考重连整面板 `#DBF5FE`，实际 `#FAFCF6`。像素值由原图局部区域读取，需同截图管线复测。
- 使用现有精确裁切或矢量图标，替换字母 v、根号式勾、圆点式名单/功能图标。胶囊里的小鼠头像与公开状态的蓝 i 必须补齐。
- 参考较淡白/绿色底、细描边与圆角有差异；不要把所有图标和卡片统一成一套泛化组件。

## 5. 实施顺序

1. 先建立逐页正确素材对应，截取**已有参考图中的插画区域**或采用已存在的精确同源素材；准备、码页、调试台不再绑定创建图。重连不用不同题材的备用图。不要再生一批“同风格”插画替换。
2. 单独修 06 鼠队场景、14 取消左右布局、16 抽屉起点/固定出口。三者不是全局参数问题。
3. 地图用同源公园底图的等比裁切，先对齐桥/亭/集合圆，再校准本人/旗帜/区域线索。正式地理地图仍运行原本地图逻辑；设计示意只进入开发预览。
4. 放大异常/结算场景，恢复12的数字胶囊、13越界层叠。逐页设面板高度，不用一套固定高度覆盖全部。
5. 调标题与图标、按钮高度/底缘/颜色；最后调页脚留白。不要在图没对上时用更多装饰掩盖。

## 6. 本轮高保真验收门槛

- 16张运行截图一对一看图；04必须对`04-hiding-v2.png`，06必须对`06-mouse-v2.png`，15对`gallery.png`。不可拿被替换草稿验收。
- **题材错误/缺失场景/左右结构错误=0**，任何一项不满足即未通过，不能写“风格一致”抵消。
- 归一化后主要锚点误差≤6dp，面板上沿≤8dp，插画宽度误差≤3%相对值，大标题墨迹字高误差≤5%。屏幕比差异优先由安全区留白吸收。
- 地图不非等比拉伸；集合圆、桥、亭三地标同时对齐。圆/头像/角色不得因背景填满而变形。
- 所有必要图标存在且形态一致；返回/详情为参考对应的描边按钮或文本横线入口，不能一概裸文本。
- 色块由同一截图管线、相同归一化区域比较；不同图片管线的轻微色彩差异不抵消构图失败。不拿全页SSIM单分掩盖缺图/错误结构。
- 界面保留真实输入、picker、复制、导航、名单、服务端倒计时、结果、二维码；不把整页PNG蒙到交互上作为“通过截图”。
