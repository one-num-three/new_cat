# 微信实际 UI 巡检 · 2026-10-11

## 结论与方法

在既有小程序内修正页面，没有另建客户端分叉。视觉基线仍为用户选定的 **02-01 明亮扁平卡通 / visual-1.0**，规则仍为 **pilot-0.2**。本轮没有生图或改动冻结美术，也没有启用技能和积分玩法。

本机微信开发工具 Stable 2.02.2608060，开发版、iPhone 12/13 模拟器，页面视口 **390×753**。官方 `miniprogram-automator` 通过本地 9420 端口读取真实页面数据与布局，切换调试台及 14 个页面/状态；截图是系统只读截取的实际模拟器，不是设计图。截图物理像素为 650×1405，包含状态栏和导航栏；不得把物理截取尺寸当作页面视口。

用户指出模拟器突然变小后，本轮停止桌面坐标点击、窗口激活与 SDK 截图。后续只切小程序路由，不调整分屏、窗口或系统缩放。中间截图/指标放在系统 Temp，完成后归档，减少 IDE 文件监控的干扰。其与小预览/路由变化的关联仅是排查假设，尚未确认微信 IDE 的根因。按钮导航是异步的，巡检明确等待完成后再读取当前页。

## 附加实际交互

- 房间预览点击取消准备：准备人数从 8 变 7、开局禁用；长昵称仍不覆盖右侧准备状态。`ready-waiting.png`。
- 抽屉旧布局覆盖结算且没有独立滚动；改为单层遮罩、固定标题和明确关闭、内部滚动。名单/事件/规则可读到末尾，关闭后猫胜结算恢复，结果未改变。`drawer-top.png`、`drawer-bottom.png`、`result-drawer.png`。
- 实际点击预览横幅返回 `pages/dev/dev`；动态码返回 `pages/map/map` 且角色为鼠。使用异步导航完成后的当前页确认，不以调用返回时的旧 Page 对象判断。

## 验证与复核

- 全部命令、退出状态、原始输出、哈希和受限副本回滚见 `ui-review/VERIFICATION.txt`。
- `after-metrics.json` 保存 15 个实际路由的 fixture 确认和元素几何；`ide-probe.txt` 为最终对应输出。真实动态状态的断网清理、旧响应/事件、身份/结果等继续由自动化行为与服务端回归覆盖。
- `baseline-hashes.json` 是本轮开始的 16 文件工作树基线；`DIFF_FILE` 比对该基线，不混入 Git HEAD 上已有的大量修改。
- `MODIFIED_FILE` 是已修改地图 WXML 的原字节副本；`ROLLBACK.sh` 只接受此证据目录下的、带专用标记的 `rollback-fixture`。已在独立副本恢复 16 个原始哈希；实际工作树仍保留修改。它不是整个项目或生产部署的一键回退。
- `discarded-attempts/` 保留早期 SDK 意外回首页的截图与指标、第一次 probe 失败；这些不作为通过证据。带 `-before-window` 的原始截图、`01-home-before.png`、`gallery-before.png` 才是有效改前观察。
