## 打开与使用

1. 微信开发者工具打开 **D:\cat-mouse-miniprogram**，编译。首页「场地地图」可切换三处公共导览。
2. 「界面调试台」底部有九龙湖、四牌楼定位演示；仅开发版可用，坐标为公开地标生成的模拟数据，不采GPS、不提交真实对局。
3. 创建真实活动时先选场地，到场确认当前集合点，再创建。游戏范围仍为集合点半径200米；校园包围盒检查不是道路通行或整个校区的活动边界。
4. 后端须同步本仓库 `cat-mouse-server/v2/` 和 `shared/`。版本接口应返回 `version:0.3.2`、`capabilities.multiVenueMaps:true`。**本轮没有部署该后端到现有域名**。旧后端会明确拒绝新校区创建，不会默认为玄武湖。
5. 客户端配置入口：`utils/config.js`，现有公网配置保留。只看公共导览/开发演示无需后端；本地回归通过隔离测试身份和临时库完成，不应在公网启用测试身份。

`MODIFIED_FILE/` 是小程序目录快照，保留资源分包；服务器源码仍以当前仓库为准，避免长期维护另一套实现。

## 验证中发现并处理的问题

- 第一轮测试遇到C盘空间不足造成PGlite初始化中止，另有旧测试fixture/硬编码路径与新场地不符；改用D盘TEMP并修正后回归通过。失败日志保留。
- 真正微信运行时不能按当前编译方式require JSON，且不存在 `wx.loadSubpackage`；改为生成JS注册表和原生分包入口，实际校区图片已显示。
- Windows `.cmd` 会把未正确引用的查询串 `&` 当命令分隔；自动化导航改为JSON参数传入运行时。原生编译打开多参数页面时显式引用查询串。
- 重新编译后，自动化调试器一度连到与可见截图不同的运行时；虽然脚本布局断言成功，截图实际为首页，**整组作废，不计通过**。`rejected/` 保存代表截图和记录。最终采用可见模拟器直接编译校区导览、断线页并人工检查；后续自动化仍需先核对通道身份，不能只看脚本PASS。
- 第一张校区断线截图错误显示玄武湖；已修复、补回归，最终 `offline-sipailou-fixed.png` 显示四牌楼且没有战术点。旧失败截图在 `rejected/`。
