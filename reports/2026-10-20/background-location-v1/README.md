# 对局后台定位 · 本地候选 API 0.5.3

日期：2026-10-20。用户确认：**微信账号尚未开通 `startLocationUpdateBackground`**。本轮代码与本地验证完成，线上仍为 0.5.2，未部署、未上传或发布本候选。

## 已实现

- 对局参与者使用微信原生后台定位接口，包含躲藏、追逐及暂停期间。准备、导览和纯公开状态页面不后台采集。
- 切后台保留一个定位监听和一个按身份授权的 WebSocket；返回前台取最新快照，同身份、同对局继续，不重复开启定位或轮询。
- 被捕、退出、取消、终局、卸载地图页、身份变更后停止定位，移除监听、计时器和隐藏页面连接。正常结束后回前台可继续看公开结算状态。
- 权限拒绝、账号接口不可用或旧微信不支持时，明确显示仅前台定位；规则抽屉提供开启及权限设置入口。切后台后不拿前台 `getLocation` 轮询冒充后台定位。
- 原生位置回调最多每 2 秒提交一次，单次请求未结束不叠加；这不是手机一定每 2 秒产生新 GPS 的承诺。后台实时连接不可用时最多每 5 秒核对一次授权状态；不缓存并补发旧坐标。
- 每条对局样本带 matchId。0.5.3 服务拒绝跨局、被捕、退出和终局后的样本，回执只带本人跟踪状态，不增加敌方坐标。仍由服务端判定失联、暂停和胜负。
- 单次定位会话设 15 分钟清理上限，覆盖现有 30 秒躲藏、6 分钟追逐及暂停上限；避免无人值守遗留采集。系统冻结或结束进程时不能承诺计时器仍执行。

游戏仍为 pilot-0.3 / reinforce-v2，人数、抓捕、线索、动态目标和胜负规则未改变。没有数据库迁移；最新位置仍只在内存，重启后重新采集。

前端配置：`utils/config.js`。当前工程保留生产 HTTPS/WSS 和关闭测试身份；在微信开发工具打开根工程。仅本地测试可启用隔离测试身份，不为此修改线上账号或权限。

平台配置入口：微信公众平台 → 开发管理 → 接口设置 → `startLocationUpdateBackground`。该接口受开放类目和账号资格限制，应以平台显示的申请要求与审核为准。另需更新隐私保护指引中前后台定位用途，用户授权“使用小程序期间和离开小程序后”。代码已声明 `requiredBackgroundModes: ["location"]` 及所需私有接口。

接口申请、授权、系统限频依据：[腾讯位置服务接口资料](https://github.com/TencentLBS/tencentmap-miniprogram-skill/blob/main/references/wx_location_api/wx.startLocationUpdateBackground.md)。代码不能代替账号开通；进程被系统结束后不能保证继续定位。

**配套更新前后端后才能按完整新实现验真机。** 线上 0.5.2 能兼容新增请求字段，但没有 0.5.3 的对局样本门禁和停止回执，不作为本候选完整验收。此前微信 0.5.2 上传任务结果未知，本轮未重复发起。

## 权限获批后的真机卡

先按 RELEASE 做无活跃局检查、备份和配套升级，再生成新的手机预览/开发版本；不要用旧手机缓存包判断本功能。Android 与 iOS 分别记录手机型号、微信版本和系统权限。

1. 正常入房、准备、开局，授权前后台定位；规则抽屉确认“后台定位已开启”。同队观察者留在前台看队友更新，敌方仍只见规则允许的线索。
2. 切到微信聊天 60 秒，在安全场地步行；返回应保持原身份、阵营、matchId 和当前进度。记录同队端实际更新间隔、准确度和是否出现失联暂停。
3. 锁屏 60 秒，再测试 2 分钟；分别用 Wi-Fi、移动网络测试。若系统停止回调或断网，现有失联暂停应生效；恢复后由组织者按原规则确认继续，不伪造在线或 GPS。
4. 做一次真实猫扫码抓鼠、一次正常终局/退出，确认出局者不再上传实时位置，也看不到实时玩家点；手机位置指示应停止。相机扫码由用户实机完成，MCP 抓捕不代替此项。
5. 拒绝后台授权后再试：应提示仅前台定位；经系统/微信设置开启后，使用规则抽屉入口重试。强制关闭微信、系统省电限制另记，不能预设持续运行成功。

将这些结果与本地自动化、模拟器、部署结果分开记录。本轮不承诺后台固定刷新间隔或公网并发量。
