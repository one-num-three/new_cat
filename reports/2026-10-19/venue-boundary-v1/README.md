# 集合点与多边形活动范围

2026-10-19，本地增量；在现有仓库演进，无第二套客户端、无公网部署或上传。

## 使用

1. 微信开发者工具打开 `D:\cat-mouse-miniprogram`，编译当前工程。
2. **创建活动 → 选择场地地图 → 地图框选范围**。在真实地图沿边界依次点选3–16个顶点；双指缩放、单指移动地图。
3. 切到「选择集合点」，在范围内点集合点，也可主动点「用我位置」采集真实GCJ-02 GPS（精度≤25m）。初始地图镜头只参考所选场地，不是本人定位。
4. 点顶点编号，再点地图即可移动；可删顶点、撤销、重画。有效后点「使用这个范围」，返回创建页创建房间。
5. 已有房间在准备页由房主点「修改集合点与范围」。服务端保存后，全员重新定位、准备；进行中（包括暂停）不能修改。
6. 开发调试台也可打开「集合点与多边形 · 开发预览」。该模式仅develop可用，不采GPS、不提交真实房间；从创建页进入的演示草稿可以带回演示创建流程。

编辑入口是按需分包 `field-editor/pages/edit/edit`。沿用Fusion Pixel、纸色/绿橙色和已批准的集合旗帜图标，保留固有图片比例及图钉锚点；未生成或覆盖美术原件。

## 服务与兼容

按根目录README的本地启动步骤运行 `cat-mouse-server`。配置入口为环境变量及 `utils/config.js`；本机测试身份仅在NODE_ENV=test、ENABLE_LOCAL_TEST_IDENTITIES=true且回环监听时启用。不要把密钥填写进源码。

- GET `/api/version` 返回0.3.3及 `capabilities.polygonVenues:true`。
- 创建房间：原创建参数不变；多边形场地附顶层 `venueFormat:'polygon-v1'`，venue为 `{lat,lng,mapId,confirmed:true,boundary:[{lat,lng},...]}`。旧服务器会拒绝该顶层字段，避免静默把范围当圆形。
- PUT `/api/v2/rooms/:id/venue`：`{commandId:UUID,expectedVersion,venue}`，操作者来自Bearer会话。只有原房主且为房间成员可修改；不能在请求里指定操作者或赢家。已有房间不能在此接口换地图身份。
- 同指令同内容重试返回已保存结果；同ID改内容拒绝，版本过期拒绝。版本冲突保留编辑草稿，读取新版本后由房主再次确认保存；不自动覆盖。
- 保存先提交数据库，再清理旧范围定位；位置带场地修订号，旧样本不能用于新范围准备/抓捕，重复越界样本不累计次数。离开编辑页后忽略晚到GPS，返回房间后旧请求不能覆盖新范围。
- PostgreSQL原JSON列保存场地、修订号、最近16条范围指令及其结果，不新增表。对局开始冻结场地，唯一终局结果附该快照。最新定位仍只在进程内存，重启需重新采集；老对局记录不回填、不覆盖。
- 原圆形范围100–500m兼容。若新集合点超出已保存房间配准控制网，会清除该房间配准并要求重新核验；不会将点强贴到图边。

## 场地协议 polygon-v1

不是新的胜负规则；原pilot人数、30秒躲藏、6分钟追逐与60%捕获目标保持。

- 单一简单多边形，3–16个顶点、GCJ-02；无孔洞或多片区域。
- 面积400–4,000,000m²；任意顶点距集合点≤3km，任意两顶点至少相距5m。
- 禁止自交、折返、重复点、退化范围；集合点必须在范围内或边线上。校区图的集合点及所有顶点必须在已登记地图坐标覆盖框内；覆盖框不是可通行区域证明。
- 服务端沿用**越界50m容差**：外侧超过50m才计越界；至少3个不同且有序样本，持续至少10秒，暂停进行中对局。不是沿多边形边线立即阻挡的硬围栏，参数尚待实测。
- 原生地图显示带填色边界；艺术图和3D模型使用相同公开边界及各自坐标参考。任意一段不能投影时整条边界不显示，并提示切实时地图，不截断成错误范围。敌方实时坐标权限不变；断线清除旧位置与边界显示。
- 房主需现场避开车道、水面、围墙和禁入区；画图不代替组织者现场确认。
