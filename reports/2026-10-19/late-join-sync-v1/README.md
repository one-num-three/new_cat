### 身份分配

| 情况 | 处理 |
| --- | --- |
| 开局前新加入 | 占一个准备名额，开始时由服务端统一随机分配 |
| 躲藏/追逐/暂停中，全新身份加入 | 原子加入，按开局比例补入猫或鼠；老玩家不重抽 |
| 已有玩家断线重连、同账号重新登录 | 保留同一个成员、阵营、被捕/退出状态；重复加入不增加人数 |
| 新人已分配阵营但尚无合格定位 | 显示“正在定位入场”，30秒内在范围内完成定位后激活；不能抓捕/展示码，也收不到玩家位置或敌方线索 |
| 入场定位超时或主动退出 | 本轮退出，不能反复入房复活；可看公开状态，下轮参与 |
| 已被捕者重连 | 保持被捕，不恢复行动或敌方视野 |

分配公式：以开局猫比例为基准，下一总人数对应猫数四舍五入；当前猫数少于此值就补猫，否则补鼠。按全体已分配身份计数，含被捕/退出者，不按在线或存活人数重抽。8人2猫6鼠时，第9人补鼠，第10人补猫，得到3猫7鼠。不同新身份并发时，以数据库提交顺序决定谁得到哪一个名额。

**本局捕获目标仍按开局鼠数计算，截止时间不延长。** 新鼠也可被捕，新猫也可抓捕。人数增长后，房间下一轮配置跟随实际猫/鼠总人数；下一轮仍需准备、生成新matchId。开局前满房继续拒绝新身份；进行中最多60个成员，这是资源保护门槛，非并发容量承诺。新玩家没有额外躲藏阶段；暂停不允许行动，入场定位的30秒窗口按墙上时间计。

这些是新增试点规则，不代表平衡已验证；中途补人会改变阵营实力，现场需记录加入时间、人数、阵营和结果。

### 全员同步

- 准备页和地图页共用 utils/room-live.js：原生WebSocket、断线回落2秒轮询、退避重连、心跳及无快照超时重建连接。连接建立后停止重复轮询；隐藏/离页关闭连接和计时器，迟到回调无效。
- 全员看到同一版本的名单、阵营、在线/被捕/入场/退出状态、人数、阶段、目标、公共事件和结果；每个人的本人身份与可见坐标由服务端单独裁剪。
- 准备页新增版本＋服务端时间门禁，晚到HTTP快照不能覆盖较新的WS状态。地图沿用同一顺序判断；重连依靠完整授权快照恢复，不靠客户端重放来裁决。
- JOIN、JOIN_READY、JOIN_EXPIRED、LEAVE 与对应角色/状态和房间版本在同一数据库事务中保存。写入失败不产生半个成员，客户端不能指定阵营或房主。
- 主动退出与断网区分：在局活跃玩家主动退出会标记退出并暂停，原成员掉线重连保持身份；房主在准备阶段离开不转移管理权限、只取消自己的准备，防止产生无主房间。
