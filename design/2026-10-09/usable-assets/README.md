# 02-01 风格透明素材与分层界面

依据 `DESIGN_BASELINE.md`、审计 PRD 和当前四个注册页面制作。素材按当前主流程使用：入房与准备 → 躲藏/追逐 → 地图线索与预警 → 抓捕码 → 被捕/暂停/重连 → 结算。**没有生成技能商店或真实抓捕二维码**；技能仍未进入试点规则。

## 可复用透明 PNG

`source/` 中每张都是单独文件，含 RGBA 透明通道，原生尺寸足够用于首页或状态卡的大插画：

| 文件 | 适用位置 |
| --- | --- |
| `cat-runner.png` | 首页头图、猫队角色介绍；已复制到运行包 `assets/brand/` |
| `mouse-runner.png` | 鼠队角色介绍、欢迎页 |
| `cat-avatar.png` / `mouse-avatar.png` | 阵营头部、名单或结算插画 |
| `park-bushes.png` | 首页、等待/空状态底部装饰 |
| `captured-mouse.png` | 被捕后公开状态说明，不表示囚禁或复活 |
| `reconnecting.png` | 连接中、失联暂停与恢复说明 |
| `cat-win.png` / `mouse-win.png` | 服务端确认结果后的阵营结算 |

模型透明插画在深色背景上可能看见极淡的半透明边缘；当前浅色页面尺寸下可使用，若以后改深色主题，应重新清理边缘并做真机检查。它们是装饰层，不能包含实时坐标或代替文字。为了控制小程序主包，当前只把 `cat-runner.png` 与已有品牌图标接入运行包，其他原图留在设计资产目录供按需接入。

## 已可直接使用的小尺寸地图标记

`assets/markers-v1/{cat,mouse,self,venue}.png` 是 96×96 的透明 PNG，对应源 SVG 在 `vector/`。它们已替换运行中地图的标记，旧 `assets/markers/` 仍保留。猫/鼠标记只用于服务端授权的队友位置；蓝色 self 是本人，绿色 venue 是集合点。**近距敌方猫不生成坐标标记；鼠端只显示预警文案。**

运行 `python render_markers.py` 可从矢量源重建 PNG，需要 PyMuPDF。源 SVG 和产物均已保存，不需运行脚本才能使用。

## 可编辑分层页面

- `home-layered-standalone.svg`：首页样稿，含 6 个命名图层：背景、天空草地、透明角色/绿植、文字、输入区、操作按钮。
- `map-layered-standalone.svg`：猫队地图样稿，含 5 个命名图层：示意地图、授权区域线索、本人/集合点、顶部状态、底部操作。
- `*-preview.png`：从对应 SVG 本地渲染的检查图，不是微信开发者工具截图。
- `home-layered.svg` / `map-layered.svg`：引用 `source/` 原图的轻量源文件；`bundle_layers.py` 把**未经像素编辑的**透明 PNG 嵌入，生成可单文件分享的 `*-standalone.svg`。

在 Inkscape 等支持 SVG 图层的编辑器打开 `*-standalone.svg` 可独立隐藏和移动各层；隐藏最底层即可得到透明背景。SVG 中的文字、底板、按钮、路线、区域圈和本人位置都是独立可编辑对象，猫鼠原图作为可替换的透明图像层。它是分层设计文件，**不是 PSD，也不是实际小程序截图**。地图底图只是构图示意，真实页面仍使用微信原生地图和服务端授权快照。

## 本轮校验

- 9 张模型素材均检测到 RGBA 和 0–255 透明通道；4 个运行标记也是 RGBA 透明 PNG。
- 两份独立 SVG 通过 XML 解析，并本地渲染为 750×1334 预览；检查后修复了首页标题区与角色遮挡。
- 真实二维码、线索坐标、胜负与倒计时继续由服务端/客户端现有流程生成，设计图中的示例数字不是运行数据。
